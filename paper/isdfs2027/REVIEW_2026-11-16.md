# ISDFS 2027 draft: Google Deep Review and author audit

This is a **pre-submission AI review**, not ISDFS peer review or a human
forensics review. The paper has not been submitted. The six-page PDF sent to
[Google Deep Review](https://research.google/deepreview/documents/829af3ca-4609-41b1-bf2f-7b37864f08d5)
on 2026-11-16 had SHA-256
`e6c64d49d7bcc16f6940c59d4c74aaccc25acd045dd222ad001f1cbe7d190b0e`.
The LaTeX source and locally compiled PDF were revised **after** that review;
the linked report annotates the submitted predecessor, not the final revision.

## Verified and addressed in the revision

- The title and main contribution now position MCPTrace as an integrated
  Volatility scan with byte export, scan-coverage accounting, multi-encoding
  carving, and a conditional evaluation. MCPRecon's published PID/VMA/offset
  provenance is acknowledged. Windows VAD traversal is implemented but is
  expressly **unvalidated in this manuscript**.
- The headline 251-versus-184 figure remains limited to all-label logical
  carving from the current client's readable bytes. MCPRecon's native whole-RAM
  scan recovered the same 184 messages within the exact-wire-present client
  set, plus 68 logged messages outside that set; the native 252 and scoped
  251/184 counts have different scopes. The conditional metric does **not**
  certify extraction at the probe's exact byte address.
- The method now states the scanner's 1 MiB read chunks, 65,536-byte object
  bound, 131,072-byte retained buffer, brace-candidate limits, classification
  rules, candidate-only ID relationship, JSON canonicalization, SSE body
  target, nominal delay timing, and the derived-stream baseline's limitations.
- A fresh analysis of the archived 27 traffic journals and 626 hash-checked
  MCPTrace export records found that all 18 present messages carved without an
  MCP label are legacy `initialize` responses: nine Node and nine .NET-legacy.
  Their `result` objects contain `protocolVersion`, `capabilities`, and
  `serverInfo`; the current classifier labels them generic JSON-RPC. All 626
  records matched logged logical messages in this controlled fixture.
- The four exact-wire-present .NET messages missed by the pinned MCPRecon CLI
  are three `notifications/initialized` messages and one `server/discover`
  request. In all four original wire serializations, a nested `params` object
  precedes `jsonrpc`. Directly applying commit `4811d04`'s `carve_json()` to
  each isolated body chose the nested opening brace (byte offsets 47, 47, 47,
  and 222 instead of byte 0), yielding a non-JSON-RPC object. This explains
  the tested wire form; it does not prove the behavior of every heap copy or
  tuned configuration.
- The non-MCP control table now separates logged messages/cases, all-label
  carving, and MCP labels. Four process snapshots yielded eight logged messages
  and 43 duplicate artifact records per scanner. Of eight constructed
  non-MCP-origin cases, MCPTrace carved eight and MCPRecon seven; both
  incorrectly MCP-labeled the same generic `result.tools` response.
- MCPRecon's journal citation now includes the publisher's volume, article
  number, and DOI. The project validation notes are labeled as such, and
  bibliography order follows first citation. The final PDF uses linked URLs;
  `pdfinfo -url` returned intact GitHub and specification URLs.

## Findings that remain limitations

- No Windows memory-image experiment validates the Windows VAD path.
- The six later Inspector/control/Codex physical-RAM images remain private
  because guest RAM may contain ephemeral keys and daemon state. The four
  Inspector/control synthetic exact-wire journals were content-audited and
  published with a six-image hash manifest in a later evidence-preparation
  step. The two Codex journals contain session metadata and remain private.
  None of the six image-level claims can be independently recomputed from the
  public bundle without the original RAM images; no new RAM archive was
  published. A later **author-run** replay of all six original archives matched
  every measured report field and per-message flag, but an external reviewer
  has not yet repeated it.
- Inspector and its controls have one capture per condition. The two Codex
  captures observe the same PID and one exchange 123 seconds apart. These
  samples do not estimate accuracy across apps, workloads, or delays.
- MCPTrace's current response heuristics both miss a valid legacy
  `initialize` response and falsely MCP-label a constructed unrelated
  `result.tools` response. The paper reports these faults; this step does not
  change the classifier or retroactively rescore the 27-image benchmark.
- An independent human domain review and, ideally, an independent rerun of
  the public 27-image procedure are still desirable before submission.

Deep Review marked the two MCPTrace project validation notes as "likely
hallucinated" because they are not indexed scholarly publications. They are
repository documentation, not journal articles; both exact files were
verified on the public GitHub research branch. The review's literal URL-space
warning was checked against the final PDF's actual link annotations.
